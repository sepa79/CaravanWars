# World Memory And Rumors

## Core Model

CaravanWars uses private actor and party memory, not a central rumor registry.

Important NPCs and parties remember what they heard, saw, inferred, or decided. A tavern is powerful because its innkeeper and guests carry many memories, not because rumors exist as global truth.

Examples of memory owners:
- innkeeper,
- escort captain,
- caravan leader,
- merchant party,
- bandit party,
- priest or bishop's agent,
- local lord's retinue,
- important servant or scout.

Ordinary soldiers, guards, and laborers can remain lightweight unless promoted by gameplay.

## Memory Entry

Suggested durable entry shape:

```json
{
  "owner_id": "party_boruta",
  "text": "Miroslaw's caravan leaves for Opole tomorrow morning.",
  "kind": "heard_rumor",
  "source_owner_id": "innkeeper_izaak",
  "heard_at_location_id": "inn_wroclaw_gate",
  "heard_at_time": "AD750-05-04T22:00",
  "tags": ["caravan", "miroslaw", "opole", "departure"],
  "credibility": 0.7,
  "salience": 0.85,
  "freshness": 0.9,
  "repeat_chance": 0.6,
  "distortion": 0.12,
  "hop_count": 1,
  "source_chain": ["Zenek", "Izaak"]
}
```

## Transfer

Most rumor spread should be cheap and code-only:

```text
source memory entry
+ meeting context
+ speaker/listener traits
-> copied memory entry for listener
```

Code updates metadata:
- credibility falls or rises based on trust and source,
- salience changes based on listener interests,
- freshness decays with time,
- repeat chance follows salience and personality,
- distortion increases with hops, alcohol, fear, distance, and low credibility.

Text is copied unchanged unless a re-render is needed.

## Re-Render

LLM re-render is occasional, not per hop.

Use it when:
- the player will see or hear the rumor,
- an important NPC or party will make a decision from it,
- distortion crosses a threshold,
- the entry has become stale, compressed, or too repetitive.

Distortion should map to allowed mutation count, not free invention:

```text
0.1-0.3: one small mutation
0.3-0.6: two or three mutations
0.6+: several mutations, still from allowed mutation families
```

Example allowed mutation families:
- time_uncertain,
- more_wagons,
- fewer_wagons,
- hurry,
- trade_goods,
- valuable_goods,
- empty_wagons,
- price_higher,
- delay,
- angry_travelers,
- animal_weak,
- needs_rest,
- stolen_goods,
- suspicion,
- patrol,
- toll_collectors,
- threat_uncertain.

## Decisions

Decision LLMs receive their actor or party memory, not objective world truth.

This rule also applies to deterministic AI. MerchantAI, MayorAI, bandits, patrols, and retinues do not have separate Godot memory. Their decisions must be based on WorldMemory entries owned by the deciding actor, party, or location.

Observations are generated by WorldSim first. WorldSim decides what the actor or party can notice from physical state and context, including stats once character sheets exist. The resulting observation is written as owner-specific WorldMemory before AI can reason over it.

This is valid gameplay:

```text
Objective truth:
Miroslaw's caravan goes to Opole.

Bandit party memory:
They heard the caravan may have extra wagons and valuable goods.

Bandit decision:
Shadow the caravan, then decide whether to attack.
```

The rumor does not create valuable cargo. It creates belief and action.

## Background Jobs

Rumor and memory work runs in the background.

The caravan does not wait for LLM jobs. A delayed result applies only if it still makes sense:
- participants are alive and valid,
- the meeting could have happened,
- the location and time still fit,
- the target route or event is not obsolete.

If a result arrives too late, discard it, degrade it, or store it as stale memory.

## Local Model Notes

Tests on the current local machine favored English internal text.

Observed roles:
- `mistral`: fastest useful background rumor mutation.
- `qwen3:8b`: controlled JSON and conservative mutation.
- `phi4`: best English player-facing rumor text, slower but good.
- `llama3.1:8b`: valid but usually too bland or occasionally wrong.

Warm calls were often sub-second. Switching models cost about 1-4 seconds, with `phi4` and `qwen3:8b` more expensive to wake. Use model queues in batches instead of alternating models for every job.
